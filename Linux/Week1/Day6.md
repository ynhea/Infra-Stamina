# Linux System Shell Script 확장

## 재사용 가능한 시스템 진단 도구 만들기

> 기존 `system_script.sh`를 확장하여, 특정 디렉토리를 인자로 받아 검사하고 결과를 리포트 파일로 저장하는 재사용 가능한 진단 도구로 발전시켰다.

---

## 1. 🎯 프로젝트 목표

* 검사할 디렉토리를 인자로 전달
* 실행 결과를 화면과 리포트 파일에 동시에 출력
* 시스템 부팅 소요 시간 확인 추가
* 반복되는 섹션 제목 출력 부분을 함수로 리팩토링
* 인자를 입력하지 않았을 때 발생하는 문제 확인

---

## 2. 📁 검사할 디렉토리를 인자로 전달
### `$1` 사용

Bash에서 `$1`은 **스크립트 실행 시 전달한 첫 번째 인자**이다.

---

## 3. 📝 실행 결과를 화면과 리포트 파일에 동시에 출력

처음에는 다음과 같이 `>>`를 사용했다.
하지만, 이 방식은 결과를 파일에 추가하지만 화면에는 출력하지 않는다.

### `tee -a` 사용

```text
명령 실행
   ↓
   tee
  ↙   ↘
화면   리포트 파일
```

---

## 4. 🚀 시스템 부팅 소요 시간 확인 추가

`systemd-analyze`를 사용하여 시스템 부팅에 걸린 시간을 확인했다.

---

## 5. 🧩 반복되는 섹션 제목 출력 부분을 함수로 리팩토링

반복되는 섹션 제목을 하나의 함수로 통일했다.

```bash
func() {
    echo "=== $1 ===" | tee -a $link
}
```

### 리팩토링 전

```bash
echo "=== 커널 버전 ===" | tee -a $link
echo "=== 배포판 정보 ===" | tee -a $link
echo "=== 현재 쉘 ===" | tee -a $link
```

### 리팩토링 후

```text
func "커널 버전"
func "배포판 정보"
func "현재 쉘"
```

---

## 6. 💻 인자를 입력하지 않았을 때 발생하는 문제 확인

다음과 같이 인자 없이 실행했다.

```bash
./system_script.sh
```

이 경우 `$1`은 비어있으므로, 다음과 비슷하게 해석된다.

```bash
touch /example
```

그 결과:

```text
touch: cannot touch '/example': Permission denied
```

가 발생했다.

하드링크와 심볼릭 링크 생성 과정에서도 `/example`, `/hard_example`, `/soft_example`처럼 루트 디렉토리를 대상으로 동작하려고 하면서 오류가 발생했다.

---

# ✅ 핵심 흐름

```text
사용자 입력
    ↓
./system_script.sh ~/Workspace
    ↓
$1 = ~/Workspace
    ↓
시스템 정보 수집
    ↓
디렉토리 inode 검사
    ↓
하드링크 / 심볼릭 링크 실험
    ↓
화면 출력
    +
report_YYYYMMDD.txt 저장
```
