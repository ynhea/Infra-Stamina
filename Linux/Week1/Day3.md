# 📘 Day 3 - inode · Directory · Mount

> **리눅스 파일시스템이 파일을 저장하고 관리하는 원리 이해**

---

# 1️⃣ 핵심 개념

| 개념 | 영어 | 한 줄 정의 |
|------|------|-----------|
| **inode** | inode | 파일 이름을 제외한 메타데이터(권한, 소유자, 크기, 위치 등)를 저장하는 구조 |
| **디렉토리** | Directory | **파일명 ↔ inode 번호**를 연결하는 매핑 테이블 |
| **마운트** | Mount | 저장장치(파티션)의 파일시스템을 특정 디렉토리에 연결하는 작업 |
| **디바이스 노드** | Device Node | 하드웨어 장치를 파일 형태(`/dev/...`)로 표현한 인터페이스 |

---

# 2️⃣ 시스템 동작 구조

## ① 파일 저장 구조

```text
┌──────────────────────────────┐
│ Directory                    │
│ (파일명 ↔ inode 번호 매핑)    │
├───────────────┬──────────────┤
│ test.txt      │ 2621447      │
│ photo.jpg     │ 2621448      │
└───────┬───────┴──────────────┘
        │
        ▼
┌──────────────────────────────┐
│ inode                        │
│ • Owner                      │
│ • Permission                 │
│ • Size                       │
│ • Link Count                 │
│ • Data Block 위치            │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│ 실제 데이터 블록 (Disk)       │
└──────────────────────────────┘
```

---

## ② mv 명령어가 빠른 이유

같은 파티션에서는 데이터를 옮기지 않고 **파일명만 변경**한다.

> ⚠️ 다른 파티션으로 이동하면 inode 체계가 달라 실제 복사 후 삭제가 이루어진다.

---

## ③ Mount 구조

```text
물리 디스크
      │
      ▼
파티션 (/dev/sda1)
      │
      ▼
파일시스템 (ext4)
      │
      ▼
Mount
      │
      ▼
/
├── home
├── data
└── var
```

### 핵심 원리

- 저장장치는 바로 사용할 수 없다.
- 파일시스템을 만든 뒤
- **Mount**를 통해 디렉토리와 연결해야 접근할 수 있다.

# 3️⃣ 실습

## ① 디스크 용량과 inode 사용량 확인

```bash
df -h

df -i
```

### 왜 이렇게 되는가?

- `df -h` → 저장 공간 사용량
- `df -i` → inode 사용량 확인

> 디스크 용량이 남아 있어도 inode가 모두 소진되면 파일을 생성할 수 없다.

---

## ② 삭제했는데 용량이 안 줄어드는 이유

```bash
lsof | grep deleted
```

### 왜 이렇게 되는가?

- 파일명은 삭제되었지만
- 프로세스가 inode를 참조 중이라
- 커널이 데이터를 제거하지 않는다.

---

# 4️⃣ 꼭 기억할 것

✅ **inode**

- 파일의 메타데이터 저장
- 파일명은 저장하지 않음

✅ **Directory**

- 파일명과 inode 번호를 연결
- 실제 데이터는 저장하지 않음

✅ **Mount**

- 저장장치를 디렉토리에 연결
- 연결되어야 접근 가능

✅ **Device Node**

- 하드웨어를 파일처럼 다룸
- `/dev` 아래 존재
