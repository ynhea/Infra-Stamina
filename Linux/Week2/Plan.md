# Week2 목표

이번 주는 Linux 커리큘럼의 세 번째, 네 번째 챕터, **"파일 관리"**와 **"권한"**을 다룬다. 1주차에서 inode가 파일의 메타데이터(소유자, 권한, 크기, 위치)를 담는 구조체라는 걸 배웠다면, 이번 주는 그 inode에 담긴 정보를 실제로 "조작"하는 명령어들을 배우는 주간이다. 월~화는 파일을 찾고, 복사하고, 압축하는 관리 능력을, 수~목은 그 파일에 누가 접근할 수 있는지를 결정하는 권한 체계를 다룬다. 이번 주의 핵심은 명령어를 실행하는 것에서 끝내지 않고, `ls -l`, `ls -li` 등의 결과를 직접 해석하는 것이다.

---

## 월요일

### 학습 목표
파일 시스템 안에서 이동하고, 복사하고, 옮기고, 지우는 가장 기본적인 조작을 원리 수준으로 이해한다. 특히 1주차에 배운 inode 개념과 cp/mv의 동작 차이를 연결해서 이해한다.

### 배울 개념
- **pwd** : 현재 작업 디렉토리의 절대 경로 출력 (Print Working Directory)
- **cd** : 디렉토리 이동 (절대경로 vs 상대경로, `.` `..` `~`의 의미)
- **ls** : 디렉토리 내용 나열 (`-l` 상세정보, `-a` 숨김파일, `-h` 사람이 읽기 쉬운 용량)
- **cp** : 파일/디렉토리 복사 (`-r` 재귀적 복사)
- **mv** : 파일/디렉토리 이동 또는 이름 변경
- **rm** : 파일/디렉토리 삭제 (`-r` 재귀적 삭제, `-f` 강제 삭제)
- **ls -li** : inode 번호와 파일 정보를 함께 확인

### 실습
```bash
mkdir -p ~/practice/sub
cd ~/practice
pwd                     # 현재 경로 확인
touch a.txt b.txt
ls -la                  # 숨김파일 포함 상세 목록
cp a.txt sub/a_copy.txt  # 파일 복사
mv b.txt sub/            # 파일 이동
rm a.txt                 # 원본 삭제 (사본은 유지됨)
```

**예상 결과**
```
$ pwd
/home/user/practice

$ ls -la
drwxr-xr-x  3 user user 4096 ...  .
drwxr-xr-x 20 user user 4096 ...  ..
-rw-r--r--  1 user user    0 ...  a.txt
-rw-r--r--  1 user user    0 ...  b.txt

$ ls sub/
a_copy.txt  b.txt
```

**왜 이렇게 되는가**
1주차에 배운 inode 개념을 다시 떠올려보자. `cp`는 원본과 완전히 다른 새 inode를 만들어 데이터를 통째로 복사하는 명령이라, 원본을 지워도 사본은 영향을 받지 않는다. 반면 같은 파일시스템 안의 `mv`는 기존 inode를 유지한 채 디렉토리 엔트리의 이름/위치를 변경한다. 단, **다른 파일시스템으로 `mv`하면 복사 후 원본 삭제와 유사하게 처리될 수 있어 inode가 유지된다고 일반화하면 안 된다.**

### 오늘 꼭 기억해야 하는 내용
- `cp` = 일반적으로 새 inode를 사용하는 별도의 파일 생성
- 같은 파일시스템의 `mv` = 기존 inode 유지
- 다른 파일시스템의 `mv` = 복사 후 원본 삭제와 유사하게 동작할 수 있음
- 상대경로(`./`, `../`)와 절대경로(`/home/user/...`)를 구분해서 쓰는 습관을 들인다

## 화요일

### 학습 목표
디스크에 흩어진 파일을 빠르게 찾고, 여러 파일을 하나로 묶어 압축하는 방법을 이해한다.

### 배울 개념
- **find** : 조건(이름, 타입, 수정시간, 크기)에 따라 실시간으로 파일시스템을 탐색
- **locate** : 미리 만들어둔 인덱스(DB)에서 파일명을 검색 (`updatedb`로 인덱스 갱신 필요)
- **tar** : 여러 파일/디렉토리를 하나의 아카이브 파일로 묶음 (압축은 하지 않음)
- **gzip** : 파일 하나를 압축 (`tar`와 결합해 `.tar.gz`로 많이 사용)

### 실습
```bash
find ~/practice -name "*.txt"       # 이름으로 검색
find ~/practice -type f -mtime -1    # 최근 1일 내 수정된 파일만
sudo updatedb                        # locate용 인덱스 갱신
locate a_copy.txt                    # 인덱스 기반 빠른 검색
grep -R "a_copy" ~/practice           # 파일 내용에서 문자열 검색

tar -czvf backup.tar.gz ~/practice   # c:생성 z:gzip압축 v:진행상황출력 f:파일명지정
tar -tzvf backup.tar.gz              # t:내부 목록 확인
tar -xzvf backup.tar.gz              # x:압축해제
```

**예상 결과**
```
$ find ~/practice -name "*.txt"
/home/user/practice/sub/a_copy.txt
/home/user/practice/sub/b.txt

$ tar -czvf backup.tar.gz ~/practice
practice/
practice/sub/
practice/sub/a_copy.txt
practice/sub/b.txt
```

**왜 이렇게 되는가**
`find`는 디렉토리 트리를 실제로 순회하며 매번 디스크(정확히는 캐시된 디렉토리 엔트리)를 뒤지기 때문에 최신 상태를 반영하지만 느릴 수 있다. `locate`는 미리 만들어둔 데이터베이스만 조회하기 때문에 훨씬 빠르지만, `updatedb`를 실행하지 않으면 방금 만든 파일은 안 나올 수 있다. `tar`는 압축이 아니라 "여러 파일을 하나로 묶는" 작업이고, 실제 용량을 줄이는 건 `gzip`(`-z` 옵션)이 담당한다는 점을 구분해야 한다.

### 오늘 꼭 기억해야 하는 내용
- `find` = 실시간 탐색(느리지만 정확), `locate` = 인덱스 기반 탐색(빠르지만 갱신 필요)
- `grep` = 파일 내용 검색
- `tar`는 "묶기", `gzip`은 "압축", `tar -t`는 내부 목록 확인

## 수요일

### 학습 목표
리눅스 권한 체계의 기본인 소유자(Owner)/그룹(Group)/기타(Other) 구조와, 그것을 조작하는 명령어를 이해한다.

### 배울 개념
- **chmod** : 파일/디렉토리의 읽기(r)·쓰기(w)·실행(x) 권한 변경 (숫자 모드 `755`, 심볼릭 모드 `u+x`)
- **chown** : 파일의 소유자(owner)를 변경
- **chgrp** : 파일의 소유 그룹(group)을 변경
- **umask** : 새 파일/디렉토리가 생성될 때 기본으로 "빼는" 권한값
- **파일과 디렉토리의 rwx 의미** : 같은 문자라도 대상에 따라 의미가 다름

### 실습
```bash
touch report.txt
ls -l report.txt          # 기본 권한 확인
chmod 640 report.txt        # 소유자 rw-, 그룹 r--, 기타 없음
chmod u+x report.txt        # 심볼릭 모드로 소유자에게 실행 권한 추가
sudo chown user2 report.txt  # 소유자를 user2로 변경
sudo chgrp dev report.txt    # 그룹을 dev로 변경
umask                        # 현재 기본 마스크 값 확인

# 디렉토리 권한 실습
mkdir permission_dir
chmod 700 permission_dir
ls -ld permission_dir
chmod 755 permission_dir
ls -ld permission_dir
```

**예상 결과**
```
$ ls -l report.txt
-rw-r--r-- 1 user user 0 ... report.txt

$ chmod 640 report.txt
$ ls -l report.txt
-rw-r----- 1 user user 0 ... report.txt

$ umask
0022
```

**왜 이렇게 되는가**
권한은 inode 안에 3비트씩 3그룹(소유자/그룹/기타)으로 저장된다. `chmod 640`처럼 숫자를 쓰는 이유는 r=4, w=2, x=1을 더한 값이 그대로 8진수 권한 비트와 1:1 대응하기 때문이다. `umask 0022`는 파일이 새로 생성될 때 기본값(디렉토리 777, 파일 666)에서 이 값만큼 권한을 "빼는" 필터 역할을 한다. 즉 서버에서 umask를 077처럼 빡빡하게 설정하면, 새로 생성되는 모든 파일이 기본적으로 타인에게 노출되지 않는다.

### ⚠ 위험한 명령어 주의
`chmod 777`은 소유자·그룹·기타 모두에게 읽기·쓰기·실행 권한을 전부 부여하는 명령이다. 웹 서버 디렉토리나 스크립트 파일에 무심코 이 권한을 주면 누구나 파일을 수정하거나 악성 코드를 심을 수 있게 되므로, "일단 되게 하려고" 습관적으로 쓰면 안 된다.

### 파일과 디렉토리 권한을 구분하기

| 권한 | 일반 파일 | 디렉토리 |
|---|---|---|
| `r` | 내용 읽기 | 내부 목록 확인 |
| `w` | 내용 수정 | 생성/삭제/이름 변경에 관여 |
| `x` | 실행 | 내부 접근(traverse) |

### 권한 숫자 해석
```text
755 = rwx r-x r-x
750 = rwx r-x ---
700 = rwx --- ---
644 = rw- r-- r--
640 = rw- r-- ---
600 = rw- --- ---
```

### 오늘 꼭 기억해야 하는 내용
- 권한 3그룹: 소유자(u) / 그룹(g) / 기타(o), 각각 r(4)·w(2)·x(1)
- `chmod`는 rwx 조작, `chown`은 소유자 변경, `chgrp`는 그룹 변경, `umask`는 생성 시 기본 권한 결정
- `ls -l` 결과를 보고 권한을 말로 해석할 수 있어야 한다

## 목요일

### 학습 목표
표준 rwx 권한으로 표현할 수 없는 특수한 권한 상황(다중 사용자 권한 관리, 임시 관리자 권한 실행, 공유 디렉토리 보호)을 처리하는 고급 권한 개념을 이해한다.

### 배울 개념
- **ACL(Access Control List)** : rwx로 표현 안 되는 세밀한 사용자별/그룹별 권한 설정 (`setfacl`, `getfacl`)
- **SUID(Set User ID)** : 실행 파일을 "소유자의 권한"으로 실행하게 만드는 특수 비트
- **SGID(Set Group ID)** : 디렉토리에 적용 시, 그 안에 새로 생성되는 파일이 부모 디렉토리와 같은 그룹을 상속받게 함
- **Sticky Bit** : 디렉토리에 적용 시, 누구나 파일을 생성할 수 있지만 삭제는 소유자만 가능하게 제한

### 실습
```bash
ls -l /usr/bin/passwd          # SUID 확인 (rwsr-xr-x)
mkdir shared_dir
chmod g+s shared_dir            # SGID 설정
chmod +t shared_dir             # Sticky Bit 설정
ls -ld shared_dir

setfacl -m u:user2:rwx report.txt   # 테스트 사용자 준비 후 ACL 확장 실습
getfacl report.txt                   # ACL 확인
```

**예상 결과**
```
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root 68208 ... /usr/bin/passwd

$ ls -ld shared_dir
drwxrwsr-t 2 user dev 4096 ... shared_dir

$ getfacl report.txt
# file: report.txt
user::rw-
user:user2:rwx
group::r--
mask::rwx
other::---
```

**왜 이렇게 되는가**
`passwd` 명령은 원래 root만 수정 가능한 `/etc/shadow`를 건드려야 하는데, 일반 사용자도 자기 비밀번호는 바꿀 수 있어야 한다. 그래서 `passwd` 실행 파일에 SUID를 걸어, 누가 실행하든 "소유자(root)의 권한"으로 잠깐 실행되게 만든 것이다. `s`가 `rws`처럼 실행(x) 자리에 표시되는 이유도 SUID/SGID가 실행 권한 비트를 확장한 것이기 때문이다. Sticky Bit가 걸린 `/tmp`가 대표적인데, 여러 사용자가 파일을 자유롭게 만들 수 있지만 남의 파일을 함부로 지울 수는 없게 막아준다. ACL은 "user2에게만 예외적으로 권한을 더 준다"처럼 소유자/그룹/기타 3단계로는 표현 못하는 경우를 위한 확장 장치다.

### ⚠ 위험한 명령어 주의
SUID를 아무 실행 파일에나 남용하면, 그 파일에 취약점이 있을 경우 공격자가 root 권한을 획득하는 권한 상승(Privilege Escalation) 통로가 될 수 있다. 실무에서는 `find / -perm -4000`으로 SUID가 걸린 파일을 주기적으로 점검하는 것이 보안 점검의 기본 루틴이다.

### 오늘 꼭 기억해야 하는 내용
- SUID = 소유자 권한으로 실행, SGID = 그룹 상속(디렉토리), Sticky Bit = 삭제는 소유자만
- ACL은 rwx 3단계로 표현 못하는 예외적인 사용자별 권한을 추가로 부여할 때 사용

## 금요일

### 프로젝트 제목
**"안전한 백업 및 아카이빙 스크립트"**

### 프로젝트 목표
월~목에 배운 파일 관리 명령어(find, tar, gzip, cp)와 권한 명령어(chmod)를 결합해, 특정 디렉토리를 압축 백업하고 그 백업 파일을 본인만 접근 가능하도록 보호하는 스크립트를 만든다.

### 구현해야 하는 기능
1. `find`로 백업 대상 디렉토리(예: `~/practice`) 안의 파일 목록을 먼저 출력
2. `tar`와 `gzip`을 이용해 해당 디렉토리를 `backup_날짜.tar.gz` 형태로 압축
3. 압축된 백업 파일을 `cp`로 별도의 백업 보관 디렉토리(`~/Backup`)에 저장
4. 백업 파일의 권한을 `chmod 600`으로 설정해 소유자 본인만 읽고 쓸 수 있게 제한
5. 백업 파일이 실제로 존재하는지 `ls -l`로 확인
6. `tar -tzf`로 압축을 풀지 않고 백업 내부 목록을 확인
7. (선택) `rm`으로 임시로 만들었던 원본 위치의 압축 파일을 정리

힌트: 날짜를 파일명에 넣고 싶다면 `date +%Y%m%d` 명령의 결과를 그대로 파일명 뒤에 이어 붙이면 된다. 아직 변수 문법을 정식으로 배우지 않았으니, 명령어를 그대로 조합해서 순서대로 실행하는 것으로 충분하다.

### 사용해야 하는 Linux 기술
`find`, `tar`, `gzip`, `cp`, `chmod`, `mkdir -p`, `ls -l`, `tar -t`

## 토요일

### 프로젝트 확장
금요일 스크립트를 **어떤 디렉토리든 백업할 수 있는 범용 백업 도구**로 발전시킨다. 대상 디렉토리와 보관 위치를 인자로 받고, 소유자/그룹까지 명시적으로 지정할 수 있게 만든다.

### 추가 기능
- 백업 대상 디렉토리를 첫 번째 인자로 받기 (`./backup.sh ~/practice`)
- 백업 보관 디렉토리를 두 번째 인자로 받기 (`./backup.sh ~/practice ~/Backup`)
- `umask`를 스크립트 시작 부분에서 `077`로 설정해, 스크립트가 만드는 모든 파일이 기본적으로 본인 외 접근 불가하게 만들기
- `chown`, `chgrp`로 백업 파일의 소유자/그룹을 명시적으로 지정 (여러 사용자가 쓰는 서버 상황 가정)
- 실행 결과(백업 성공 여부, 백업 파일 크기 등)를 `backup_log_날짜.txt`로 저장

힌트: `$1`은 첫 번째 인자, `$2`는 두 번째 인자다. `umask`는 그 뒤에 실행되는 모든 파일 생성 명령에 영향을 주므로 스크립트 맨 위에 두는 것이 안전하다.

### 리팩토링 포인트
- 백업 대상/보관 경로가 하드코딩되어 있지 않고 인자로 잘 분리되었는지
- 인자를 아예 안 주고 실행했을 때 스크립트가 이상한 경로에 백업을 시도하지 않는지 (본격적인 인자 검증은 다음 주 Shell Script 챕터에서 다룬다. 지금은 문제를 "인지"만 해두면 된다)
- 백업 파일 권한이 600으로 잘 걸렸는지 매번 `ls -l`로 확인하는 습관
- `tar -tzf`로 백업 내부가 예상과 같은지 검증하는 습관

# 이번 주 핵심 개념 5가지
1. **cp vs mv** — 데이터 레벨 복사(새 inode) vs 메타데이터 레벨 이동(inode 유지)
2. **find vs locate** — 실시간 탐색(정확·느림) vs 인덱스 탐색(빠름·갱신 필요)
3. **tar + gzip** — "묶기"와 "압축"은 서로 다른 작업이며 함께 조합해 사용한다
4. **chmod/chown/chgrp/umask** — 권한 3그룹(소유자/그룹/기타)과 생성 시 기본 권한 제어
5. **SUID/SGID/Sticky Bit** — 표준 rwx로 부족한 특수 상황(임시 권한 상승, 그룹 상속, 삭제 제한)을 위한 확장 권한

# 실무 활용 사례
- 크론(cron)으로 매일 새벽 `tar czvf` 백업 스크립트를 자동 실행하고, 오래된 백업은 `find -mtime +30 -delete`로 자동 정리한다.
- 로그 로테이션(logrotate)이 오래된 로그 파일을 `.gz`로 압축해 디스크 공간을 절약한다.
- 여러 개발자가 함께 쓰는 디렉토리에 SGID를 걸어, 누가 파일을 만들든 같은 그룹 소유권을 유지하게 만들어 권한 충돌을 줄인다.
- 보안 점검 시 `find / -perm -4000 -type f`로 SUID가 걸린 파일을 주기적으로 스캔해 불필요한 권한 상승 통로를 찾아 제거한다.
- 배포 서버에서 `umask 027`을 기본값으로 설정해, 새로 생성되는 모든 설정 파일이 기본적으로 그룹 외 사용자에게 노출되지 않게 한다.
