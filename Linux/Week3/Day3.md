# 📘 Day 3 — Process, PID/PPID
> **핵심 :** Process, PID, PPID, fork(), exec(), Thread, Daemon  

---

## 1️⃣ 목표

명령어를 실행했을 때 리눅스 내부에서 프로세스가 어떻게 생성되고 식별되는지 이해하고, 현재 실행 중인 프로세스를 조회하는 도구를 익힌다.

---

## 2️⃣ 핵심 개념

| 개념 | 영어 | 한 줄 정의 |
|---|---|---|
| **프로세스** | Process | 실행 중인 프로그램의 인스턴스, 커널이 관리하는 독립적인 실행 단위 |
| **프로세스 식별번호** | PID | 각 프로세스에 부여되는 고유 번호 |
| **부모 프로세스 번호** | PPID | 그 프로세스를 만든 부모 프로세스의 PID |
| **스레드** | Thread | 프로세스 안에서 메모리를 공유하며 동시에 실행되는 더 작은 실행 흐름 |
| **데몬** | Daemon | 로그인 세션과 무관하게 백그라운드에서 계속 실행되는 프로세스 |

---

## 3️⃣ 왜 필요한가

```text
사용자 → Shell → Kernel → Hardware
```

사용자가 Shell에 명령을 입력하면 그 명령은 결국 **프로세스**로 실행된다.

```text
사용자가 bash에 'sleep 300' 입력
        │
        ▼
bash가 새 프로세스를 만듦
        │
        │ fork()
        ▼
자식 프로세스 생성
        │
        │ exec()
        ▼
sleep 프로그램으로 교체
        │
        ▼
커널이 PID를 부여하고 관리
```

서버 운영에서는 다음과 같은 문제를 해결하기 위해 프로세스 구조를 이해해야 한다.

- 어떤 프로세스가 CPU를 많이 사용하는가?
- 특정 프로세스는 어떤 프로세스에서 만들어졌는가?
- 서비스가 죽었는데 어떤 프로세스가 다시 실행했는가?

---

## 4️⃣ 내부 동작 원리

### ① 모든 프로세스는 하나의 뿌리에서 시작한다

```text
                    PID 1
              (systemd 또는 init)
                      │
        ┌─────────────┼─────────────┐
        │             │             │
      PID 612       PID 890       PID 1200
      (sshd)       (nginx)        (bash 로그인 쉘)
        │                             │
      PID 950                      PID 1400
    (ssh 세션)                    (내가 입력한 명령)
```

리눅스가 부팅되면 `init/systemd`가 **PID 1**로 시작한다.

이후 생성되는 프로세스는 부모-자식 관계를 가지며 프로세스 트리 구조를 이룬다.

### ② fork()와 exec()

```text
[부모 프로세스: bash, PID 1400]
        │
        │ fork()
        ▼
[자식 프로세스: bash 기반, PID 1500, PPID 1400]
        │
        │ exec()
        ▼
[최종: sleep 프로세스, PID 1500, PPID 1400]
```

```text
fork()
→ 자식 프로세스 생성

exec()
→ 현재 프로세스의 프로그램 내용을 새로운 프로그램으로 교체
```

즉,

> **fork = 프로세스 생성**  
> **exec = 프로그램 교체**

---

## 5️⃣ Process vs Thread

프로세스는 서로 독립적인 메모리 공간을 가지며, 스레드는 같은 프로세스 내부에서 메모리를 공유한다.

```text
┌───────────────────────────────┐
│ Process A                      │
│ ┌─────────┐  ┌─────────┐     │
│ │Thread 1 │  │Thread 2 │     │
│ └─────────┘  └─────────┘     │
│       └── 같은 메모리 공유 ──┘ │
└───────────────────────────────┘

┌───────────────────────────────┐
│ Process B                      │
│       독립된 메모리 공간       │
└───────────────────────────────┘
```

| Process | Thread |
|---|---|
| 서로 독립된 메모리 공간 | 같은 프로세스의 메모리 공유 |
| 프로세스 간 격리가 강함 | 같은 프로세스 내부에서 실행 |
| 생성/전환 비용이 상대적으로 큼 | 생성/전환 비용이 상대적으로 가벼움 |

## 6️⃣ Daemon

데몬은 로그인 세션과 무관하게 백그라운드에서 계속 실행되는 프로세스다.

예:

```text
sshd
systemd
crond
```

이름 끝에 `d`가 붙는 경우가 많다.

```text
sshd   ← ssh + daemon
systemd ← system + daemon
crond  ← cron + daemon
```

## 9️⃣ ps -ef 컬럼 이해

예:

```text
UID   PID  PPID  C STIME TTY      TIME CMD
root    1     0  0 09:00 ?    00:00:02 /sbin/init
root  612     1  0 09:00 ?    00:00:00 /usr/sbin/sshd
user 1400  1380  0 09:05 pts/0 00:00:00 bash
```

| 컬럼 | 의미 |
|---|---|
| UID | 이 프로세스를 실행한 사용자 |
| PID | 프로세스 고유 번호 |
| PPID | 부모 프로세스 번호 |
| C | CPU 사용률 관련 값 |
| STIME | 시작 시각 |
| TTY | 연결된 터미널 (`?`이면 연결된 터미널이 없음) |
| TIME | 누적 CPU 사용 시간 |
| CMD | 실행된 명령어 |

### PID와 PPID

```text
부모 프로세스
PID = 1400
      │
      ▼
자식 프로세스
PID = 1500
PPID = 1400
```

> **자식 프로세스의 PPID = 부모 프로세스의 PID**

## 🔟 PID 1과 PPID 0

PID 1은 부팅 과정에서 시작되는 최초의 사용자 공간 프로세스다.

```text
PID 1
systemd
  │
  ├── 서비스
  ├── sshd
  ├── 로그인 셸
  └── 기타 프로세스
```

PID 1은 일반적인 부모 프로세스에 의해 생성된 것이 아니므로 PPID가 0으로 표시되는 형태를 볼 수 있다.

```text
PID 1
PPID 0
```

## 1️⃣1️⃣ 고아 프로세스 (Orphan Process)

부모 프로세스가 먼저 종료되었지만 자식 프로세스가 아직 실행 중인 경우다.

```text
부모 프로세스 종료
        │
        ▼
자식 프로세스는 계속 실행
        │
        ▼
새로운 부모에게 재입양
```

### 고아와 좀비 구분

```text
고아(Orphan)
→ 부모가 먼저 종료됨
→ 자식은 아직 실행 중

좀비(Zombie)
→ 자식이 먼저 종료됨
→ 종료 상태가 부모에게 아직 회수되지 않음
```

## 1️⃣2️⃣ ps aux vs ps -ef

```text
ps aux
→ BSD 스타일
→ %CPU, %MEM 등의 정보를 보기 편함

ps -ef
→ UNIX 스타일
→ UID, PID, PPID 등의 관계를 확인하기 편함
```

둘 다 프로세스를 확인할 수 있으며 출력 형식과 컬럼 구성이 다르다.

## 🧠 1️⃣3️⃣ 오늘의 핵심 정리

```text
Process
→ 실행 중인 프로그램의 인스턴스

PID
→ 프로세스의 고유 번호

PPID
→ 부모 프로세스의 PID

fork()
→ 자식 프로세스 생성

exec()
→ 프로세스의 프로그램 교체

Thread
→ 프로세스 내부에서 메모리를 공유하는 실행 흐름

Daemon
→ 백그라운드에서 계속 실행되는 프로세스

ps
→ 프로세스 조회

pstree
→ 프로세스 부모-자식 관계 확인

top
→ 실시간 프로세스 상태 확인
```

### ⭐ 꼭 기억하기

> **PID = 나의 번호**  
> **PPID = 나를 만든 부모의 번호**
>
> **fork = 자식 프로세스 생성**  
> **exec = 프로그램 교체**
