# 📘 Day 4 — Foreground/Background, Zombie, kill

> 프로세스가 살아있는 동안 어떤 상태를 가질 수 있는지 이해하고, 시그널을 이용해 프로세스를 안전하게 제어하는 방법을 익힌다.

---

## 1. Target

- Foreground와 Background의 차이
- Zombie 프로세스가 생기는 이유
- Orphan과 Zombie의 차이 구분
- `kill`이 단순히 "프로세스를 죽이는 명령"이 아니라 **시그널을 보내는 명령**임을 이해하기
- `SIGTERM`과 `SIGKILL`의 차이 이해

---

## 2. 핵심 개념

| 개념 | 영어 | 한 줄 정의 |
|---|---|---|
| **포그라운드** | Foreground | 터미널을 점유하며 실행되는 작업 |
| **백그라운드** | Background | 터미널을 점유하지 않고 뒤에서 실행되는 작업 |
| **좀비 프로세스** | Zombie | 자식은 종료됐지만 부모가 종료 상태를 회수하지 않아 프로세스 테이블에 남은 상태 |
| **시그널 전송** | Signal | 프로세스에 특정 동작을 요청하거나 지시하는 방법 |
| **kill** | `kill` | 프로세스에 시그널을 보내는 명령어 |

> ⚠️ `kill`이라는 이름 때문에 "프로세스를 죽이는 명령"이라고 생각하기 쉽지만, 본질은 **시그널을 전달하는 것**이다.

---

# 3. 왜 필요한가?

실행 중인 프로세스를 종료하는 방법은 여러가지다!

```text
서버에서 이상 동작하는 프로세스 발견
        │
        ▼
   바로 강제 종료?
        │
        ▼
      위험할 수 있음
        │
        ├─ 파일을 쓰는 중일 수 있음
        ├─ 네트워크 연결을 정리해야 할 수 있음
        └─ 작업을 마무리해야 할 수 있음
        │
        ▼
먼저 "정상적으로 종료해 달라"고 요청
        │
        ▼
     SIGTERM
        │
        ▼
그래도 종료되지 않을 때
        │
        ▼
     SIGKILL
```

따라서 프로세스 관리에서는 **정상 종료와 강제 종료를 구분하는 것**이 중요하다.

---

# 4. Foreground vs Background

## 4.1 Foreground
- 현재 터미널에서 사용자의 입력을 받으며 실행되는 작업이다.

```text
$ sleep 300
          │
          └── 300초 동안 현재 터미널을 점유

$ _
```

즉, **현재 터미널을 점유하고 있는 작업**이라고 생각하면 된다.

---

## 4.2 Background

- 명령어 뒤에 `&`를 붙이면 Background 작업으로 실행할 수 있다.

```text
$ sleep 300 &
[1] 12345

$ _
```

- `[1]` → 현재 쉘에서 관리하는 작업 번호(Job ID)
- `12345` → 프로세스의 PID
- 명령 실행 후 바로 프롬프트가 돌아온다.

즉, 다른 명령을 계속 입력할 수 있다.

---

## 4.3 `jobs`, `fg`, `bg`

현재 쉘이 관리하는 작업은 `jobs`로 확인할 수 있다.

### Foreground → 일시 정지

Foreground 작업이 실행 중일 때:

```text
Ctrl + Z
```

를 누르면 작업이 일시 정지(Stopped)된다.

---

# 5. Zombie 프로세스

## 5.1 Zombie란?

Zombie는 **실행이 끝난 자식 프로세스의 종료 정보가 아직 회수되지 않은 상태**다.

중요한 점은 Zombie가 **실행 중인 프로세스가 아니라는 것**이다.

---

## 5.2 정상적인 종료 흐름

```text
자식 프로세스 실행
        │
        ▼
자식 프로세스 종료
        │
        ▼
커널이 종료 상태를 보관
        │
        ▼
부모가 wait() 호출
        │
        ▼
종료 상태 회수
        │
        ▼
프로세스 테이블에서 제거
```

부모 프로세스가 `wait()`를 호출하면 자식의 종료 상태를 회수할 수 있다.

---

# 6. Orphan과 Zombie 구분하기

둘은 자식 프로세스와 부모 프로세스의 관계에서 발생하지만 상황이 반대다.

| 구분 | Orphan | Zombie |
|---|---|---|
| 부모 | 먼저 종료 | 살아있을 수 있음 |
| 자식 | 계속 실행 중 | 이미 종료됨 |
| 핵심 문제 | 부모가 없음 | 종료 상태가 회수되지 않음 |
| 특징 | 다른 프로세스가 입양 | 프로세스 테이블에 종료 정보가 남음 |

```text
Orphan
부모가 죽음 → 자식은 살아 있음

Zombie
자식이 죽음 → 부모가 회수하지 않음
```

---

# 7. `kill` — "죽이기"가 아니라 시그널 보내기

기본 사용법:

```bash
kill [옵션] PID
```

---

## 7.1 `SIGTERM` — 정상 종료 요청

```bash
kill -15 <PID>
```

`SIGTERM`은 프로세스에게:

> "가능하면 작업을 정리하고 정상적으로 종료해."

라고 요청하는 시그널

```text
SIGTERM 수신
    │
    ▼
현재 작업 정리
    │
    ├─ 파일 처리 마무리
    ├─ 네트워크 연결 정리
    ├─ 임시 작업 정리
    └─ 필요한 상태 저장
    │
    ▼
정상 종료
```

단, `SIGTERM`을 받았다고 해서 **모든 프로그램이 반드시 즉시 종료되는 것은 아니다.**

프로그램은 이를 처리하거나 무시할 수 있다!!

---

## 7.2 `SIGKILL` — 강제 종료

```bash
kill -9 <PID>
```

`SIGKILL`은 커널이 프로세스를 강제로 종료하도록 하는 시그널이다.

프로세스가 직접 처리하거나 무시할 수 없다.

```text
SIGKILL
   │
   ▼
커널이 강제 종료
   │
   ▼
프로세스가 정리 코드를 실행할 기회 없음
```

따라서 15 시그널 시도 이후, 9를 실행해야 한다!

---

## 7.3 `SIGTERM` vs `SIGKILL`

| 항목 | `SIGTERM` | `SIGKILL` |
|---|---|---|
| 번호 | 15 | 9 |
| 의미 | 정상 종료 요청 | 강제 종료 |
| 프로그램이 처리 가능? | 가능 | 불가능 |
| 프로그램이 무시 가능? | 가능 | 불가능 |
| 정리 작업 수행 가능? | 가능 | 불가능 |
| 일반적인 사용 순서 | 먼저 시도 | 최후의 수단 |

### 핵심 흐름

```text
kill -15 <PID>
      │
      ▼
정상 종료 기다림
      │
      ├── 종료됨 → 끝
      │
      └── 계속 실행 중
              │
              ▼
       상황을 확인한 뒤
       kill -9 <PID>
```

> ⚠️ `kill -9`를 습관적으로 먼저 사용하는 것은 피한다.

---

# 8. 왜 `kill -15`를 먼저 사용하는가?

프로세스가 종료되기 전에 정리해야 할 작업이 있을 수 있기 때문이다.

예:

```text
프로세스 실행 중
      │
      ├─ 파일 쓰기
      ├─ 네트워크 연결
      ├─ 메모리/리소스 사용
      └─ 애플리케이션 상태 관리
      │
      ▼
SIGTERM
      │
      ▼
프로그램이 종료 절차 수행
      │
      ▼
정상 종료
```

반면 `SIGKILL`은 프로그램에게 종료 절차를 수행할 기회를 주지 않는다.

따라서 일반적인 운영에서는 **SIGTERM을 먼저 보내고, 필요한 경우 SIGKILL을 최후의 수단으로 사용한다.**

---

# 9. 주요 시그널

| 시그널 | 번호 | 의미 |
|---|---:|---|
| `SIGHUP` | 1 | 터미널 연결 종료. 프로그램에 따라 설정 재로드 등에 사용 |
| `SIGINT` | 2 | 인터럽트. 일반적으로 `Ctrl + C` |
| `SIGKILL` | 9 | 강제 종료. 처리하거나 무시할 수 없음 |
| `SIGTERM` | 15 | 정상 종료 요청 |
| `SIGSTOP` | 19 | 프로세스 일시 정지. 처리하거나 무시할 수 없음 |

전체 시그널 목록은 다음 명령으로 확인 가능.

```bash
kill -l
```

---

# 10. Zombie는 왜 `kill`로 없앨 수 있는가? → 없다

Zombie는 이미 종료된 프로세스다.

따라서 실행 중인 코드가 없고 시그널을 받아 처리할 프로세스도 없다.

```text
Zombie
  │
  └── 이미 실행 종료
          │
          ▼
       실행 코드 없음
          │
          ▼
      kill로 직접 제거 불가
```

해결 방향은 Zombie 자체를 죽이는 것이 아니라 **부모 프로세스가 종료 상태를 회수하도록 만드는 것**이다.
따라서 프로그램 코드의 `wait()` 처리를 점검하거나, 상황에 따라 부모 프로세스를 재시작하는 방식으로 문제를 해결한다.

---

# 11. 오늘의 핵심 정리

```text
Foreground
→ 현재 터미널을 점유하는 작업

Background
→ 터미널을 점유하지 않고 실행되는 작업

Zombie
→ 자식은 종료됐지만 부모가 종료 상태를 회수하지 않은 상태

Orphan
→ 부모가 먼저 종료됐지만 자식은 계속 실행 중인 상태

kill
→ 프로세스에 시그널을 보내는 명령

SIGTERM (15)
→ 정상 종료 요청
→ 프로그램이 처리 가능

SIGKILL (9)
→ 강제 종료
→ 프로그램이 처리하거나 무시할 수 없음

일반적인 종료 순서
→ SIGTERM 먼저
→ 필요할 때 SIGKILL
```
